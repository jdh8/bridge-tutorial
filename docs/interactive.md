# 互動練習

2026-10-11 從[影片系列](video.md)的評估轉過來的方向：與其拍影片或替書補圖，不如讓讀者在網頁上自己叫牌。比對之後做成了本書自己的揭曉模式。

## 為什麼不是影片

- **書的教法是先叫再對答案。** 每章的練習表和[實戰篇](deals.md)都是這樣。影片只能看，會直接念出答案。
- **實戰篇要讀者只看一家。** [實戰篇](../src/deals.md)第 2 步要讀者「其他三家的牌你也要當作沒看到」。靜態頁面四家同時攤開，做不到；互動頁面可以只顯示輪到的那一家。
- **數字還沒定案。** [第四部](part4.md)和[第五部](part5.md)的範圍隨時會改，第三部也還是暫時版。影片錄了就改不了，網頁改一行就好。
- **讀者是 BTU 新生。** 社課有人當面講解，書加上自己動手練，比書加上影片更補得上缺口。

影片的事情還沒結束：書沒有講打牌，打牌示範仍然適合拍。等數字定案再說。

## 為什麼不是補圖

書的資料是手牌、叫牌過程和點數範圍。現在的表格已經夠讀：四家牌表圈出發牌的人、紅底標身價、叫牌過程收在 `<details>` 裡。[影片評估](video.md)說的「零視覺素材」是對影片而言，對書沒有缺口。

## 做法：借用 pons-web

../pons/web 已經在瀏覽器裡跑：Practice 分頁讓你選一個座位，其他三家由 2/1 機器人叫，叫完攤開四家並列出雙夢家結果；Edit 分頁可以貼 PBN。`deals.py` 已經會輸出每副牌的 PBN。

所以只差兩步：

1. pons-web 接受網址帶進一副牌，直接開 Practice，例如 `#practice?pbn=N:...&dealer=N&vul=NS`。現在的 hash 只用來切分頁。
2. `deals.py` 替實戰篇每副牌產生「在 pons 上叫這副牌」的連結。

## 風險：機器人不照本書的制度叫

pons-web 的機器人叫的是 `american()`，不是本書。第一到三部的暫時版、本書刻意的簡化，機器人都不知道。新生和機器人搭檔，叫出書上沒教的叫品，反而會混淆。

所以要先拿實戰篇的牌比對機器人和書的答案：

- **差得少**：直接接上連結。
- **差得多**：改做本書自己的「一次看一家、一圈一圈揭曉答案」模式，用 mdbook 的 `additional-js`，不靠 pons。

## 結論：揭曉模式

改做本書自己的「一次看一家」模式，答案就是書上的叫牌過程，不靠機器人。

- `reveal.js` 由 `book.toml` 的 `additional-js` 載入，資料全部從頁面上的表格讀：第一張表是四家的牌，`<details>` 裡的表是叫牌過程，`<li>` 是解說。不必另外維護一份資料，改了 [src/deals.md](../src/deals.md) 就跟著變。
- 每副牌上方一個「一次看一家」按鈕。按下去只留輪到那一家的牌，答案收起來；「對答案」填上一格叫品、加上那一條解說，「下一家」換人。叫完就攤開四家、打開原本的 `<details>`，連最後一段合約說明一起看。
- 解說和叫品的對應：解說照叫牌順序排，粗體是「北 1NT」這種座位加叫品。沒有解說的叫品（多半是 Pass）就跳過；「東、南、西 Pass」這種合寫的，三家共用一條，只放一次。2026-10-11 檢查過 32 副牌，每一條解說都對得上。之後寫新的牌，粗體照這個格式就好。
- 沒有 JavaScript 時頁面和原本一樣。列印時不顯示按鈕。

pons-web 的連結可以等以後再加，當作「和機器人自由練習」，不是實戰篇的答案。前提是上面五副可疑的先在 pons 修好。
