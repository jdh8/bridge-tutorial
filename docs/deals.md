# 實戰篇的形式

[二十副牌，全部叫一遍](../src/deals.md)的形式是 2026-10-06 定的。

## 四家都攤開，讀者四家都叫

每副牌給發牌者、身價和四家的牌，讀者從發牌者開始輪流叫，輪到誰只看誰的牌，叫完再點開答案。

考慮過只讓讀者叫一家或一對。沒有採用，因為各章的練習表已經在練「一家、叫到一半」；實戰篇要補的是完整的過程：誰開叫、敵方進不進來、什麼時候停。作者補充的理由是，這樣也訓練從四個座位看同一副牌。代價是讀者看得到同伴的牌，要自律。四個人也可以照表把牌發出來，上桌叫一遍。

## 版面

- 牌和叫牌過程都用「西｜北｜東｜南」四欄的表格，和[叫牌那一章](../src/auction.md)的叫牌表同一個順序。直著看就是同一家的牌和叫品，手機上也不會太寬。牌譜常見的十字形要另外寫 HTML，沒有採用。
- 答案收在 `<details>` 裡，是瀏覽器原生的摺疊，不必加套件。mdbook 內建的 Rust 功能（playground、`editable`、藏行）只對 Rust 程式碼有用。mdbook-quiz 可以做選擇題，但要多一個 preprocessor，題目另外寫成 TOML，也沒驗證過支不支援 mdbook 0.5；想做「逐個叫品作答」時再考慮。
- 解說每個叫品一條，附點數，連回對應的章節。最後一段說合約和合計點數。
- 標題只寫「第 N 副」，不寫主題，主題也混著排。標題寫了「競叫」，讀者就知道敵方會叫牌。

## 身價

發牌者和身價照複式橋牌第 1--20 號牌的輪法。

身價除了文字，也用表頭的顏色表示：有身價的一對紅底白字，無身價不上色。每副牌從牌表到 `</details>` 包在 `<div class="vul-ns">`、`vul-ew` 或 `vul-both` 裡，雙方無身價就不包；CSS 在 `style.css`，用欄位的奇偶選座位（北、南是偶數欄）。

一開始無身價用綠底，仿牌套的紅綠。作者不要綠色：螢幕的紅、綠 subpixel 位置不同，紅底和綠底並排時邊緣會錯開。所以無身價維持預設的表頭。

## 牌是設計出來的

二十副都是照制度設計的牌，不是隨機發的。每一副要符合：

- 四家的每一個叫品都照本書的制度，**包括派司**。敵方派司的牌，要對過蓋叫、迫伴賭倍、竄叫和平衡叫的條件。例如同伴蓋叫之後有四張支持的弱牌該跳加叫，敵方加叫之後停在二線、敵花短的牌該平衡叫；設計時要避開，或把它當成主題。
- 最後的合約攤開四手牌做得成（第 17 副是被賭倍的 1♠ 倒三，比南北自己成局的分數多）。

驗證的方法：

```sh
python3 deals.py | (cd ../dds-bridge && cargo run -q --release --example solve-pbn)
```

`deals.py` 檢查每副牌是四家各 13 張、52 張不重複，把四家的大牌點印到 stderr，並輸出 PBN；`../dds-bridge` 的 `solve-pbn` 算出每個座位、每種王牌的雙夢家磴數。改了任何一張牌都要重跑。
