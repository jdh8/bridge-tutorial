# 實戰篇的形式

[三十二副牌，全部叫一遍](../src/deals.md)的形式是 2026-10-06 定的，第 1--20 副同時寫成；第 21--32 副是 2026-10-11 加的，專挑前二十副沒測到的工具。

## 四家都攤開，讀者四家都叫

每副牌給發牌者、身價和四家的牌，讀者從發牌者開始輪流叫，輪到誰只看誰的牌，叫完再點開答案。

考慮過只讓讀者叫一家或一對。沒有採用，因為各章的練習表已經在練「一家、叫到一半」；實戰篇要補的是完整的過程：誰開叫、敵方進不進來、什麼時候停。作者補充的理由是，這樣也訓練從四個座位看同一副牌。代價是讀者看得到同伴的牌，要自律；後來改成預設「一次看一家」的揭曉模式，見[互動練習](interactive.md)。四個人也可以照表把牌發出來，上桌叫一遍。

## 版面

- 牌和叫牌過程都用「西｜北｜東｜南」四欄的表格，和[叫牌那一章](../src/auction.md)的叫牌表同一個順序。直著看就是同一家的牌和叫品，手機上也不會太寬。牌譜常見的十字形要另外寫 HTML，沒有採用。
- 答案收在 `<details>` 裡，是瀏覽器原生的摺疊，不必加套件。mdbook 內建的 Rust 功能（playground、`editable`、藏行）只對 Rust 程式碼有用。mdbook-quiz 可以做選擇題，但要多一個 preprocessor，題目另外寫成 TOML，也沒驗證過支不支援 mdbook 0.5；後來的「逐個叫品作答」也沒用它，見[互動練習](interactive.md)。
- 解說每個叫品一條，附點數，連回對應的章節。最後一段說合約和合計點數。
- 標題只寫「第 N 副」，不寫主題，主題也混著排。標題寫了「競叫」，讀者就知道敵方會叫牌。

## 身價

發牌者和身價照複式橋牌第 1--32 號牌的輪法。

身價除了文字，也用表頭的顏色表示：有身價的一對紅底白字，無身價不上色。每副牌從牌表到 `</details>` 包在 `<div class="deal">` 裡，南北有身價加 `vul-ns`，東西有身價加 `vul-ew`，雙方有身價兩個都加；CSS 在 `style.css`，用欄位的奇偶選座位（北、南是偶數欄）。

一開始無身價用綠底，仿牌套的紅綠。作者不要綠色：螢幕的紅、綠 subpixel 位置不同，紅底和綠底並排時邊緣會錯開。所以無身價維持預設的表頭。

顏色在五個 theme 下比較過（2026-10-06）：

- **紅底不跟 theme 換**，固定 `#b22` 配白字，對比 6.2:1。花色用的 `--red` 不能拿來當底色：深色 theme 的 `#f66` 當底色是粉紅，白字只剩 2.9:1；Rust 的 `#a21` 偏橘褐，更靠近 Rust 的表頭。
- **Rust 的無身價改成中性灰**。Rust 預設的表頭 `#b3a497` 是暖褐色，和紅色同色系，看起來像褪色的紅，和紅底的亮度對比也只有 2.6:1（light 是 3.9:1）。所以 `.rust .deal` 把 `--table-header-bg` 換成 `hsl(60, 5%, 70%)`，也就是 Rust 的 `--quote-border`。只改實戰篇，其他表格保留暖褐。
- 深色 theme 的表頭和紅底亮度相近（約 1.5:1），但藍灰和紅的色相差得遠，不必改。
- 無身價不填色（BBO 的紅白）也試過：深色 theme 的表頭會融進頁面，沒有採用。

class 的設計：

- 換的是變數，不是 `th` 的背景。mdbook 的 `thead tr` 有一圈同色的 1px 邊框，只改 `th` 會留下暖褐的框線。
- 變數管的是整張表，不分座位，所以無身價不設 `nv-ns`、`nv-ew`，一個 `deal` 就夠。無身價就是沒有 `vul-*`，也不會寫出 `vul-ns nv-ns` 這種矛盾的組合。
- 原本的 `vul-both` 拆成 `vul-ns vul-ew`，兩個 class 各管自己的兩欄。
- 發牌者在表頭畫圈，`deal` 再加 `dealer-n`、`dealer-e`、`dealer-s` 或 `dealer-w`。圈是 `th` 的 `radial-gradient` 背景圖，顏色用 `currentColor`，紅底上自動變白圈；不必改表頭的 Markdown。和 `vul-*` 的規則都用 `background`，所以發牌者的規則只設 `background-image`，放在後面，才不會蓋掉紅底。叫牌過程的表頭也會圈，提醒從哪一家開始叫。

## 牌是設計出來的

每一副都是照制度設計的牌，不是隨機發的。每一副要符合：

- 四家的每一個叫品都照本書的制度，**包括派司**。敵方派司的牌，要對過蓋叫、迫伴賭倍、竄叫和平衡叫的條件。例如同伴蓋叫之後有四張支持的弱牌該跳加叫，敵方加叫之後停在二線、敵花短的牌該平衡叫；設計時要避開，或把它當成主題。
- 最後的合約攤開四手牌做得成（第 17 副是被賭倍的 1♠ 倒三，比南北自己成局的分數多）。

驗證的方法：

```sh
python3 deals.py | (cd ../dds-bridge && cargo run -q --release --example solve-pbn)
```

`deals.py` 檢查每副牌是四家各 13 張、52 張不重複，把四家的大牌點印到 stderr，並輸出 PBN；`../dds-bridge` 的 `solve-pbn` 算出每個座位、每種王牌的雙夢家磴數。改了任何一張牌都要重跑。

第 21--32 副的設計另有幾個考量：

- 每副只放一個新工具，再配一兩個前面已經測過的工具當背景，免得解說塞太多連結。
- 第 27 副刻意做成兩邊都剛好八磴（2♥ 和 2♠ 都做得成），這是平衡叫那一章「你派司，敵方得 110 分」的原型。
- 第 29 副的北是[王牌滿貫](../src/slam/trump.md)那一章的例子，南換了幾張小牌；叫牌過程把扣叫、問關鍵張、問王牌 Q 三個工具一次走完，是全書最長的叫牌過程。
- 第 25 副的南故意只有兩張黑桃：本書沒有寫敵方扣叫（Michaels）之後答叫者怎麼叫，有三張支持的牌會沒有叫品。
- 第 32 副的北故意只有 8 點：9 點就會叫 1NT，支持賭倍之後的無王也沒有寫。

還沒有出現的工具：5–4 高花的邀請、Smolen、Texas、Gerber、Unusual 2NT、借一張 K 的平衡賭倍（第 27 副是敵方停在二線，不算點數）、平衡位置的 1NT 和 2NT、2♣ 之後的正答叫、跳叫新花、1♠ - 3♠ 的邀請加叫、1♠ - 4♠ 的竄叫加叫、弱牌在開叫者兩門裡挑一門、二線蓋叫、1♥ 之後表示四張黑桃的負性賭倍、二線蓋叫的罰放、跳蓋叫。要換牌的話，可以從這裡挑。
